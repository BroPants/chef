# Chef 微信小程序 - 产品需求文档 (PRD)

> 版本：v1.1  
> 更新日期：2026-04-13

---

## 1. 产品概述

| 项目 | 说明 |
|------|------|
| 产品名称 | Chef |
| 产品类型 | 微信小程序 |
| 产品定位 | 通过拍摄已做好的菜品，识别菜品并展示所需食材与制作方法；同时主动推送灵感，帮助用户发现新菜品 |
| 目标用户 | 想学做菜、想复刻某道菜、对食材用量不熟悉，以及希望获得每日下厨灵感的用户 |

## 2. 核心功能需求（v1.0，已完成）

### 2.1 菜品识别（P0）

| 需求ID | 需求描述 | 验收标准 |
|--------|----------|----------|
| R-001 | 拍照识别 | 支持小程序内调用相机拍照 |
| R-002 | 相册选择 | 支持从相册选择已有照片 |
| R-003 | 识别结果 | 返回菜品名称及置信度 |
| R-004 | 识别失败处理 | 无法识别时给予明确提示，引导重拍或更换图片 |
| R-005 | 多菜品识别 | （P1）可识别图片中多道菜并分别返回 |

| 需求ID | 需求描述 | 验收标准 |

| R-007 | 制作步骤 | 分步骤展示做法，支持图文说明 |
| R-008 | 预估时长 | （P1）展示预估制作时间 |
| R-009 | 难度等级 | （P1）展示难度（简单/中等/困难） |
| R-010 | 营养价值 | （P2）展示营养成分、热量等 |

### 2.3 用户功能

## 3. v1.1 新增需求

> 目标：从「工具」升级为「灵感来源」，提升用户主动打开率与使用时长

### 3.1 首页每日灵感推荐（P0）

**背景**：用户打开小程序时往往没有明确目标菜品，提供随机推荐可降低使用门槛，增强「逛」的感觉。

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|----------|--------|----------|
| R-101 | 随机菜品推荐卡片 | P0 | 首页操作入口下方展示一张推荐卡片，包含菜品图片、菜品名称、简短描述（如难度、时长） |
| R-102 | 每次打开随机刷新 | P0 | 每次进入首页（onShow）从推荐池中随机取一道菜，保证不重复连续推荐 |
| R-103 | 点击推荐直接进菜谱 | P0 | 点击推荐卡片直接跳转该菜品的菜谱详情页，无需拍照识别 |
| R-104 | 换一换按钮 | P1 | 卡片右上角提供「换一换」，手动刷新推荐 |
| R-105 | 菜品图片来源 | P0 | 后端维护一套精选菜品图片库（含菜品名、图片 URL、简短描述），供前端随机抽取 |

**推荐卡片结构示意：**

```
┌─────────────────────────────────────────┐
│  [菜品图片，16:9 或 3:2，圆角]           │
│                              [换一换 ›]  │
│  今日灵感                               │
│  红烧狮子头                             │
│  🕐 45 分钟  ·  ⚡ 中等难度              │
└─────────────────────────────────────────┘
```

### 3.2 菜谱页外部内容链接（P0）

**背景**：用户学做菜时往往需要参考视频或图文教程，B 站和小红书是国内最主要的食谱内容平台，将相关链接聚合在菜谱页可显著提升实用性。

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|----------|--------|----------|
| R-106 | B 站视频推荐 | P0 | 菜谱页底部展示 1～3 条相关 B 站视频（封面图、标题、UP 主、播放量），点击跳转 B 站 |
| R-107 | 小红书笔记推荐 | P0 | 菜谱页底部展示 1～3 条相关小红书笔记（封面图、标题、作者），点击跳转小红书 |
| R-108 | 内容来源标签 | P0 | 每条外链清晰标注来源平台（B 站 / 小红书），避免用户困惑 |
| R-109 | 内容获取方式 | P0 | 后端在菜品识别成功后，根据菜品名调用 B 站搜索 API 和小红书相关接口（或维护人工筛选的优质链接库）获取推荐内容 |
| R-110 | 外链跳转方式 | P1 | 优先使用小程序 webview 打开，降低跳出损耗；若平台限制则引导用户复制链接在浏览器打开 |
| R-111 | 内容区块位置 | P0 | 放置在菜谱步骤之后、页面底部，区块标题「相关视频 / 博主教程」 |

**外部内容区块结构示意：**

```
─────────────────────────────────────────
  相关教程
  ┌──────────────────────────────────────┐
  │ [B站] [封面] 【红烧狮子头】做法超详细...│
  │         UP主：某厨房  · 23.4万 播放   │
  └──────────────────────────────────────┘
  ┌──────────────────────────────────────┐
  │ [小红书] [封面] 妈妈级红烧狮子头，入口...│
  │         作者：某某美食               │
  └──────────────────────────────────────┘
─────────────────────────────────────────
```

### 3.3 烹饪步骤语音播报（P1）

**背景**：用户下厨时双手不方便操作手机，支持步骤语音播报可大幅提升操作体验。

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|----------|--------|----------|
| R-112 | 步骤语音朗读 | P1 | 菜谱页提供「开始语音播报」按钮，依次朗读每个步骤，读完自动停顿等待 |
| R-113 | 播报控制 | P1 | 支持暂停/继续、上一步/下一步手势控制 |
| R-114 | 技术方案 | P1 | 使用微信小程序 `wx.createInnerAudioContext` + TTS 接口（如讯飞/腾讯云）合成语音 |

### 3.4 食材购物清单（P1）

**背景**：用户确定要做某道菜后，需要去超市购买食材，一键生成购物清单可减少遗漏。

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|----------|--------|----------|
| R-115 | 生成购物清单 | P1 | 菜谱食材列表支持勾选，点击「生成购物清单」将未勾选食材导出 |
| R-116 | 清单分享 | P1 | 可将购物清单以文本形式复制或分享给家人 |
| R-117 | 本地缓存清单 | P2 | 清单保存至本地，下次进入小程序可继续查看 |

### 3.5 按季节 / 节日推荐（P2）

**背景**：中国饮食与节令关联密切，结合时节推荐更有共鸣感。

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|----------|--------|----------|
| R-118 | 节令感知推荐 | P2 | 根据当前日期自动识别节气/节日（如春节、清明、端午），在首页推荐对应时令菜品 |
| R-119 | 推荐标签标注 | P2 | 推荐卡片展示「应季」「节日特供」等标签，增强点击欲 |

### 3.6 以食材反查菜谱（P2）

**背景**：用户冰箱里有剩余食材但不知道做什么，可以反向输入食材查可做的菜品。

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|----------|--------|----------|
| R-120 | 食材输入 | P2 | 首页新增「我有这些食材」入口，支持输入或从历史菜谱食材中选取 |
| R-121 | 反查菜谱列表 | P2 | 根据输入食材返回可做的菜品列表（优先展示食材匹配度高的） |

## 5. 技术需求（v1.1 补充）

### 5.1 推荐菜品数据接口

| 端点 | 说明 |
|------|------|
| `GET /api/recommendations/daily` | 返回随机推荐菜品（含图片 URL、名称、难度、时长） |
| `GET /api/recommendations/seasonal` | 返回当前节令推荐菜品列表 |

后端维护一个精选菜品库（≥ 100 道），每次随机抽取并记录最近推送历史避免连续重复。

### 5.2 外部内容接口

| 端点 | 说明 |
|------|------|
| `GET /api/content/external?dish=红烧狮子头` | 返回该菜品的 B 站视频列表 + 小红书笔记列表 |

**数据策略**（二选一）：
- **方案 A（推荐）**：维护人工筛选的优质内容库，按菜品名索引，保证质量可控
- **方案 B**：接入 B 站开放 API（`search/type=video`）实时搜索；小红书暂无开放 API，采用人工整理或第三方数据

### 5.3 TTS 语音合成

使用讯飞 WebAPI 或腾讯云 TTS，将步骤文本转为音频 URL，前端通过 `wx.createInnerAudioContext` 播放。

## 6. 非功能性需求（更新）

| 类别 | 要求 |
|------|------|
| 性能 | 推荐卡片图片懒加载，首屏渲染 < 1s |
| 性能 | 外部内容接口响应 < 2s，超时展示「暂无相关内容」 |
| 体验 | 推荐卡片换一换动画过渡流畅（fade or slide） |
| 体验 | 外链跳转前给出平台提示（「即将跳转至 B 站」） |
| 合规 | 外部链接需确认平台方允许第三方小程序引用，避免侵权 |
| 合规 | 菜品推荐图片版权需有授权或使用自建图库 |

## 7. 风险与依赖（更新）

| 类型 | 描述 | 应对 |
|------|------|------|
| 小红书接口限制 | 小红书无官方开放 API，抓取存在封禁风险 | 初期人工维护精选笔记库，长期关注平台开放生态 |
| 图片版权 | 精选菜品图片需授权 | 使用 CC 协议图片或自拍菜品图；可与内容平台合作 |
| TTS 费用 | 语音合成按字数计费 | 首次生成后缓存音频 URL，避免重复合成 |
| 推荐质量 | 随机推荐命中率影响用户印象 | 引入点击率反馈，低点击菜品降权 |
